# Five-hour working guide

Use actual remaining time; the official start is not known yet. This is a planning aid,
not a gate that blocks a useful change at an arbitrary minute. Replan scope, not the clock.

| Budget | Useful outcome |
|---|---|
| First ~20 min | Person, painful task, promised before/after, closest alternative; choose one |
| Next ~30 min | Small test of the deciding assumption with a fair baseline/checker |
| Until ~220 min | One complete working path, tested as it grows |
| Final ~80 min | Held-out checks, real interface/export, fixes, 90-second demo; reserve ~15 min for recovery |

If dependency setup consumes the experiment budget, choose a reachable smaller path.
If the promised difference disappears, narrow the claim or change direction early.
Late additions need a direct user benefit and enough time to verify them. Keep the last
working path runnable. Scale benchmark size before running, never discard failures afterward.

Agents are optional: give one unresolved question to novelty_scout (need/change),
feasibility_scout (technical path) or independent_reviewer (evidence/correctness).
Default 5-minute task, 200-word answer. Run independent questions together only when this
saves elapsed time. One integrator owns shared edits; specialists remain read-only.
Use at most three children, stop completed work, and run serially if tools are unavailable.
No repeated research, progress meetings, approval forms or reports to satisfy a schedule.
