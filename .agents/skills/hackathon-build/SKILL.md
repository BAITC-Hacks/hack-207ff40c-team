---
name: hackathon-build
description: Deliver the smallest working path that changes the selected user's outcome; BUILD only.
---

Confirm BUILD authorization; read the decision card and current handoff. Start with the
riskiest assumption about the promised user change. In a short experiment (normally
30 minutes), compare the current/simple workflow with our addition on identical inputs;
use independently checked results. Stop or narrow if the benefit or correctness fails.

Build one input -> computation -> useful action/result -> export path. Reuse familiar
components. Add a feature only if it enables the promised outcome or verifies it.
Check data access, relevant licenses and critical dependencies when needed; no new
checklist or architecture layer. Escalate a blocked prerequisite early and use a smaller
reachable path. Scope work to actual remaining time and preserve demo/check time.

Use a small fixed case set before tuning; retain errors and boundary failures. Exercise
the actual interface and export. Configure meaningful checks.json commands and paired
adapters when those test the claim; specialized user-task measures may need another
checker. Label simulated inputs/replay. Report actual results, limits and borrowed code
in EXPERIMENT/ATTRIBUTION, with a short HANDOFF. Parent owns integration; request a
specialist only when a bounded parallel question will save time.
